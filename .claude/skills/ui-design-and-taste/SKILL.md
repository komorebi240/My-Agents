# UI design and visual quality

Use for visual design decisions; ui-ux-review covers reviewing an existing result.
Do not load both automatically for a minor style fix.

1. Inspect the affected page, shared primitives, tokens and nearby patterns.
2. Establish the primary action and hierarchy; reuse the product's visual language.
3. Use consistent typography, spacing, semantic colors and restrained elevation.
4. Choose deliberate desktop/mobile table and navigation behavior.
5. Cover keyboard/focus and relevant loading, empty, error and disabled states.
6. Inspect rendered results at representative viewports and shared-component consumers.

Avoid decorative motion, nested cards and one-off variants without a functional reason.
Preserve theme, localization and existing behavior.

For a substantial redesign, read only relevant sections of
[visual-quality.md](references/visual-quality.md): forms/tables, navigation/responsiveness,
typography/spacing, or visual QA. Do not load the reference for every UI edit.
